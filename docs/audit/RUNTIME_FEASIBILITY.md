Pyodide 运行所需的 5 个文件合计 **13,531,207 字节（13.53 MB，约 12.90 MiB）**：Wasm 9.60 MB、标准库 ZIP 2.55 MB、运行时 JS 1.27 MB、锁文件 0.12 MB。仅在选择 Python 时加载；全部 `dist/` 文件目前约 21.90 MB。官方部署说明称带全部第三方包的完整发行包超过 200 MB；这里仅提供核心文件。已附 [MPL-2.0 许可文本](../../public/assets/pyodide/LICENSE)与[来源和哈希清单](../../public/assets/pyodide/manifest.json)。Python 标准库随附[上游许可证](../../public/assets/pyodide/LICENSE.PYTHON)；后续增加第三方包应逐包检查许可与下载体积。Worker 不构成强安全沙箱；当前适合用户自己编写的示例，不对外承诺隔离不可信代码。Rust 编译器仍未纳入版本管理。

连续编辑时复用已经加载的 Pyodide Worker，只保留最后一次待运行代码；本轮代码的变量空间彼此隔离。正在执行的代码超过 3 秒仍会终止 Worker，若此时有较新的代码等待运行，再重新加载运行时并执行最新版本。这样避免普通编辑反复初始化运行时，但不能避免超时后的重新加载。

从档案重复打开同一语言会保留编辑内容、运行结果与现有 Worker；加载过程中再次打开 Python 也不重启初始化。离线调度检查使用替身 DOM、Worker 与时钟，验证重复打开、最新代码优先、过期结果丢弃、离开时终止、闲置释放及超时恢复；真实运行时测试与浏览器实测另行进行。

实验台只在打开且页面可见时启动示例。离开展台或页面进入后台时停止尚在加载或执行的任务，并取消待运行编辑；后台打开语言也不会初始化新运行时。已就绪且空闲的 Python Worker 设置 3 分钟释放定时，方便短时间内返回；浏览器可能延后后台定时器，不能把它视为严格的内存释放期限。再次进入可见实验台时对被中断的任务重新执行最新草稿，已完成结果直接复用。替身调度检查覆盖这些页面可见性事件，真实浏览器仍需复测。这个策略减少无意的后台计算，但静态运行文件仍需要首次下载。本机预览对运行文件使用固定内容哈希 ETag，未变化时请求返回 304，不重复传输文件正文；生产环境的缓存效果取决于实际托管配置。

两种运行时均在捕获阶段限制日志为 20,000 个字符，JavaScript 最多捕获 200 次日志调用；发生异常时为真实异常信息保留空间。JavaScript 的独立线程测试验证异步输出、异常和达到上限后停止格式化额外日志；Python 测试使用仓库里的实际 Pyodide 运行时，在 Node 中适配文件加载，验证真实执行、变量空间隔离与大量日志后的异常。Node 检查不证明浏览器资源加载或页面调度正常，仍需浏览器实测；捕获限制也不构成程序整体内存限制。

本机预览会按 `Accept-Encoding` 的质量参数选择 Brotli（质量 5）、gzip 或原文件；不同编码有独立 ETag，并设置 `Vary: Accept-Encoding`，避免互用缓存。ZIP 和 PNG 不再次压缩。`npm run runtime:budget` 使用同一压缩参数离线测量以下正文体积；本次为 Node v25.8.0，压缩结果可能随 Node 的压缩库版本变化，原始文件哈希仍保持固定。

## 浏览器与服务端的成本取舍

当前 Python 和 JavaScript 的小型示例优先在浏览器运行：服务器只托管静态文件，计算发生在访问者设备上。Python 首次使用的原始文件约 13.53 MB，本机 Brotli 传输正文约 6.04 MB，且浏览器承担初始化、内存及执行时间。实际静态托管仍有带宽费用，不能声称完全没有服务器成本。若同一访问者反复使用，缓存和 Worker 复用会摊薄启动与传输成本。

服务端执行可减轻用户设备负担，并允许安装浏览器内难以提供的编译器，但每次运行都消耗服务端 CPU 与内存，还需要并发限制、超时、隔离、限流和运维。是否更省钱取决于活跃用户数、每人运行次数、程序资源消耗、静态流量单价与计算资源单价；目前没有实际流量和托管报价，不给虚假的盈亏平衡点。Rust、C++ 等语言应分别核实浏览器内编译器的大小和可用性，必要时再提供受控服务端编译；不能把预编译好的 Wasm 展品冒充用户源码的编译结果。
