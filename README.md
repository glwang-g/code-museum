# Code Museum

**The Museum of Programming Languages** — 一座可以漫游、检索、比较和动手运行的编程语言博物馆。

[进入正式网站](https://codemuseum.freexlib.com) · [查看源码仓库](https://github.com/glwang-g/code-museum) · [在线阅读本文档](https://github.com/glwang-g/code-museum/blob/master/README.md)

## 这是一个什么项目

Code Museum 把编程语言当作一座可以探索的博物馆：你可以沿着时间长河浏览语言，打开关系谱系查看设计来源，搜索完整馆藏，比较不同语言解决同一问题的方式，也可以在实验台中编辑并运行一部分真实代码。

项目的核心想法很简单：语言之间的关系应该有出处，运行结果应该来自真实环境，缺少证据的地方应该明确标成待核，而不是用看起来合理的故事填满地图。

## 你可以体验什么

- **展厅与阅读**：以有来源的主题展品和5条完整导览开始，进入独立语言阅读页，再将眼前的原样代码送到实验室；全量馆藏、图谱与原始档案始终可达。当前功能与验收见 [部署记录](docs/DEPLOYMENT.md)。
- **时间长河**：默认按年代分组阅读233个有线索地图节点，可筛选年代并进入语言阅读；计算史背景单独标注，完整馆藏始终可检索。“完整图谱”保留原地图浏览。
- **关系谱系**：默认以“已记录输入—当前语言—后续”三栏阅读直接关系，手机纵向排列；设计影响、后继/扩展与实现生态分层显示，卡片可展开原文、哈希和待核说明。“完整图谱”保留缩放、上游/下游、1–3层及全部前序后续操作；带层级等参数的旧链接仍打开图谱。
- **语言展品**：JavaScript、Python、Lua、Scheme、C、C++、Java、Rust 的档案新增设计背景、核心规则、原创注释代码与版本边界，可继续阅读设计依据或进入实验台改写。
- **语言检索**：搜索名称、别名、创造者或馆藏 ID，支持全量馆藏和性质筛选。
- **语言实验台**：编辑带高亮的示例代码，保存本机草稿，导入或下载代码，并查看真实诊断。JavaScript、Python、Lua、Scheme 支持浏览器内运行；远端已接入56门，连同浏览器模式共59个可执行语言节点（Python重叠）。免令牌模式最多允许5个活跃执行会话，第6个提示“当前访问比较多，请稍后重试。”；具体语言、版本、部署状态和边界见 [执行说明](docs/EXECUTOR.md) 与 [免令牌说明](docs/GUEST_EXECUTION.md)。
- **按需检查与讲解**：点击“检查代码”才调用大模型，检查当前代码并给出讲解、错误提示或尽量保持原意的修改建议；可以补充预期行为。建议不会自动覆盖或运行原稿，绿色仅表示模型未发现明显问题。见 [检查与纠错说明](docs/AI_EXPLANATIONS.md)。
- **语言对比**：用相同主题比较 C/C++、Java/C#、Python/JavaScript、Lua/Scheme 等语言；入口位于“学习”分区，阅读、对比、实验室往返保留语言与题目，继续任务保留草稿，明确载入示例可撤销。见 [学习路径与测速](docs/LEARNING_FLOW.md)。
- **学习导览**：5 条路线、27 个步骤，每步说明观察内容、动手操作及预期；阅读任务和真实运行任务分别说明，JavaScript 入门路线的变量、分支、循环、函数、列表练习及原有 Scheme 平方练习支持真实输出与预期比较及本机完成记录；只核对输出，不评判代码写法。
- **分享与恢复**：URL 保留语言、关系层、展开范围、关系依据、阅读或实验台主题，支持刷新及前进后退；分享链接不包含代码、标准输入或执行会话凭据。恢复实验台链接不会自动执行保存的代码。
- **出处与说明**：通过本地模糊搜索和分类查找62项运行时、数据、参考资料及馆藏边界；目录和详情各自滚动，保留完整版本、适配、许可与来源链接，并显示由源码和固定数据生成的内容版本。
- **留言板**：写下意见或建议，留言会公开显示在留言板日志中；如已配置通知服务，维护者会收到提醒。服务只保存昵称、留言内容、当前页面位置及用于限流的匿名标识哈希，不记录 IP、邮箱、账号或原始匿名标识；发送失败时不会显示为已送达。

### 分级导航与界面统一

新版统一正文、辅助文字、卡片、按钮与明暗内容层次，主导航收敛为“探索／学习／实验室”三个分区。探索包含主题展厅、全量馆藏、时间长河和关系谱系；学习包含学习导览和语言对比，二级导航只显示当前分区的栏目。语言阅读属于探索中的馆藏详情，实验室保留结果与讲解页签，“出处”位于右上角。手机采用三项底部主导航。此版已于2026-11-12正式发布，本机和正式验收范围见 [发布记录](data/audit/hierarchy-navigation-deployment.json)，设计与实施见 [项目上下文](docs/PROJECT_CONTEXT.md)。

### 正式版与保留的方案

正式改版在 `src/` 中实现，沿用完整的执行、模型、草稿、导览、对比与出处功能。运行 `npm run build && npm run preview` 查看；构建同时从固定的 `archive/classic-ui/` 源码生成 `/classic/` 原版，原版不依赖本机临时文件或旧服务器release。

早期本地方案A、B仍保留用于设计对照，不是当前正式应用：`npm run modern:preview` 打开 <http://127.0.0.1:4188/>，`npm run gallery:preview` 打开 <http://127.0.0.1:4189/>。这些简化Demo不进入普通发布包，范围见 [方案A](docs/MODERN_PREVIEW.md) 与 [方案B](docs/GALLERY_PREVIEW.md)。

“完整图谱”沿用时间长河插画；默认年代索引与关系阅读采用新的阅读布局。插画是视觉资产，不是语言关系的证据，原始插画保存在 `archive/assets/`，不进入站点构建。

## 当前馆藏与证据范围

当前固定 PLDB 快照包含 5,155 条记录，其中 4,608 条被来源标记为语言；经证据筛选的地图节点为 233 个，60 条语言记录已核实语法与实现，11 条记录有历史一手资料。

当前关系盘点共有 461 条关系：451 条设计/历史关系、10 条实现与生态关系。其中 178 条已有匹配的原文摘录，280 条仍只有来源字段，另有 3 条仅有引用出处；后两类都不能视为已经完成历史核实。常显设计层仍有 2 个缺口：Assembly、XSLT；另有 6 项年代提示。

这些数字只描述当前固定输入和审计状态，不表示已经找全所有语言、所有上游或所有历史关系。可以从 [关系状态](docs/audit/RELATIONSHIP_STATUS.md) 和 [研究待办](data/audit/research-gap-report.json) 查看细节。

## 运行环境和边界

- 浏览器中的 JavaScript 使用 Worker 执行，并有输出和时间限制。
- Python 的本地模式使用固定版本 Pyodide；Lua 使用 Wasmoon/Lua 5.4.5；Scheme 使用 BiwaScheme 0.8.3。它们都明确说明兼容范围，不冒充完整系统环境。
- 远端执行通过同源网关接入受限容器；免令牌模式要求worker使用gVisor/runsc，最多5个活跃浏览器会话、每会话1个在途任务，两台机器合计执行并发2。源码只在任务期间进入临时执行容器，不存入网站数据库。会话闲置5分钟释放，限流不等于识别5个真实用户。
- 语言实现、方言和预算固定在清单中，工具链留在服务端，不随网页下载。任务不在线安装依赖；“59个可执行节点”包含解释器、转换器与仿真器，不等于59种原生编译器，也不表示任意第三方包或历史方言均受支持。
- 尚未接入网页运行时的语言不会显示伪造的运行结果；本机通过也不等于网页或生产环境已经接入。
- 留言板依赖正式站后端 `/api/messages`；本地预览或后端未接入时会明确显示服务不可用，不会显示任何伪造留言。只有服务器配置了 SMTP 凭据才会发信，未确认送达的留言保持待通知状态。
- 浏览器Worker、容器和gVisor各有边界；资源和隔离检查不构成不存在逃逸漏洞或全语言语义认证。尚未满足runsc健康条件的节点不会对guest开放。

完整的运行范围、版本、资源限制和本机/生产边界见 [执行说明](docs/EXECUTOR.md) 与 [本机环境说明](docs/LOCAL_ENVIRONMENT.md)。

## 当前进度与待办

截至2026-11-12，正式版已完成整体改版、分级导航与组件统一、学习路径衔接，以及时间长河和关系谱系的默认阅读视图。最新功能发布为 `c22dad1`，见 [发布与验收记录](data/audit/hierarchy-navigation-deployment.json)；各次部署的测试范围与限制记录在 [部署说明](docs/DEPLOYMENT.md)，历史测试数量不作为当前全量验收数量。

原B组37门已按P2、P3顺序完成固定工具链、真实执行和页面接入，公开固定输入已推送并经CI离线重建验证。BCPL的六项上游私有材料仍按明确的输入策略单独保存，公共仓库足以重建网站，完整BCPL镜像重建另需合法持有且哈希匹配的私有包。逐门历史与语义边界见 [构建计划](docs/audit/RUNTIME_BUILD_PLAN.md) 和 [执行说明](docs/EXECUTOR.md)。

- 继续为常显标签和高价值关系寻找可回溯的一手资料，减少“只有来源字段”的关系。
- 研究 XSLT、Zig 和具体汇编方言的历史设计来源；不把参考文献、ABI、编译目标或语法相似性直接当成继承关系。
- 继续区分馆藏原始字段、人工校订、设计证据和实现/生态证据。
- 逐步补充更多真实运行环境，但保持每种语言的版本、许可、限制和核验记录可见。
- 整理服务端磁盘容量，并在实际使用后评估冷启动和模型响应；当前独立任务容器包含启动成本，已有 [耗时基线](docs/LEARNING_FLOW.md)，尚未实现常驻语言容器池。

现有 6 项年代警告和 Assembly/XSLT 两个缺口在相关档案或关系依据中显示证据分诊与下一步；分诊不代表新增一手史料核实，原待核计数继续保留。

研究过程见 [项目上下文与交接](docs/PROJECT_CONTEXT.md) 以及 [关系研究记录](docs/audit/)。

## 从源码运行

需要 Node.js 22 或更高版本；完整默认测试与审计另需 Python 3、rsync 和可写临时目录。网站构建不需要联网下载数据，也不需要先执行 `npm install`：浏览器资源和网站所需公开元数据均为固定项目输入。BCPL采用 [受限输入策略](data/runtime-input-policy.json)，从公开源码也能离线构建相同网页；重建BCPL镜像的额外输入见 [执行说明](docs/EXECUTOR.md)。

```sh
npm run build
npm run preview
```

然后打开 <http://127.0.0.1:4173>。开发时也可以使用：

```sh
npm run dev
```

构建和测试：

```sh
npm test
npm run audit
npm run relations:audit
npm run build
```

`npm test` 在独立临时目录重建网站，检查构建可复现、坏输入保护及服务边界；部分用例监听本机回环地址，不需要公网或Docker。已安装Chrome/Chromium时，在另一终端启动 `PORT=4191 npm run preview`，再核验当前正式布局：

```sh
npm run site:browser
npm run interface:browser
npm run learning:browser
node scripts/check-explore-reading.cjs
npm run controls:browser
npm run credits:browser
```

前四项默认连接4191，后两项自建临时预览。普通静态预览不连接远端执行和模型后端；模型预览见 [配置说明](docs/AI_EXPLANATIONS.md)。双节点真实执行验收需要SSH、预备镜像和显式联调操作，会上传执行器模块、公开数据及测试程序，范围见 [本机环境说明](docs/LOCAL_ENVIRONMENT.md)。旧地图专项脚本保留作历史或专项诊断，不代替当前整站验收。

## 数据、许可与文档

- 固定 PLDB 快照、审查记录和关系证据位于 `data/`。
- 网站源码位于 `src/`，原始静态资源位于 `public/`，构建入口位于 `scripts/`。
- 不要直接编辑 `dist/`；它由构建生成，也不作为源码输入提交。
- 数据来源、运行时许可和版本入口在网站“出处与说明”页公开；上游许可仍以各项目自己的声明为准。
